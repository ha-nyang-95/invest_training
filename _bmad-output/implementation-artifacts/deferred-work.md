If NTP steps the wall clock backward after a successful run, `last_success_seconds > time()` and the Prometheus expression `time() - last_success > 120` becomes negative → alarm never fires during the skew window. Mitigation is a `now = max(int(time.time()), prev_last_success)` clamp, but the true root-cause is outside Athena (NTP policy on Trading PC). Revisit if we observe this in practice or when Story 1.10 adds `ntpd`/`chrony` configuration to the ops substrate.
- systemd unit absolute-path hardcoding — `infra/systemd/athena-logger-sync.service` inlines `/home/khuk0/invest_training/.venv/bin/python` + `/home/khuk0/invest_training/scripts/emit_logger_sync_metric.py`. Single-host/UID assumption is valid for V1.0 (Khuk0 personal system). Root-cause fix is an installer template pattern: `infra/systemd/athena-logger-sync.service.in` with `${ATHENA_HOME}`/`${ATHENA_USER}` placeholders that the installer (or its Story 1.7 Logger PC equivalent) renders via `envsubst` into `/etc/systemd/system/`.
